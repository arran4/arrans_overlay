# Gaps and Issues in Overlay Workflow Builder Generator v0.1.27

## 1. Incorrect checkout action version
The generator incorrectly uses `actions/checkout@v7` instead of `actions/checkout@v4`. `v7` does not exist for `actions/checkout`. The latest major version is `v4`.

## 2. Unwanted inclusion of `metadata/md5-cache` in git add
The generated workflow includes `git add metadata/md5-cache/ || true` in the commit step. The repository no longer tracks the `metadata/md5-cache` or `metadata/md5-dict` directories in version control. Therefore, the tool should not automatically stage and commit `metadata/md5-cache/`.

## 3. `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true` removed
The generator drops `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true` from the `env` section of the workflow.

## 4. Workarounds and manual edits overwrite
The tool overwrites manual changes in the generated files (e.g., custom `pkg_postinst` in `gocdm-bin`, `sed` logic in `flutter-jules-bin`, `rust-v` extraction in `codex-bin`, and `dosym` in `go-playerctl-bin`). This means regenerating blindly breaks existing custom logic. Furthermore, the generator overwrites licenses that were previously specified accurately manually with `unknown`.

## 5. Variable regression in `superfile-bin`
In `app-misc/superfile-bin-update.yaml`, the generator emitted `${TAG}` inside the `Binary` path string, but bash evaluates this as empty, whereas the manual edit used `${tag}` which resolves to the correct extracted version in the bash loop.

## Failed adaptations report
- `app-misc/gocdm-bin`, `dev-util/codex-bin`, `media-sound/go-playerctl-bin`, `app-misc/superfile-bin`, `app-misc/flutter-jules-bin`, `www-misc/which_browser` have manual edits and were NOT safely regenerated by the generic builder configs. Applying the generated output indiscriminately causes severe regressions.
- The `g2 metadata` command relies on the user providing correct fields (person/project etc.), which is hardcoded as `-m "gentoo@arran4.com:Arran Ubels:person"` and works, but might not be dynamically generated correctly based on the actual maintainer if others were to use the tool.

## Feature Requests

### 1. Mechanism for Preserving Custom Ebuild Bash Logic
**Issue:** The generator completely replaces the entire `.github/workflows/*-update.yaml` file on generation. Many workflows have critical custom bash scripts injected into the ebuild `cat <<EOT` block (such as `pkg_postinst` tweaks, manual `sed` text patching, `dosym` for binaries, and extracting customized version strings).
**Feature Request:** Introduce a configuration directive or templating mechanic (e.g., `CustomEbuildBlock` or recognizing `# BEGIN MANUAL EDIT` / `# END MANUAL EDIT` markers in existing workflows) to preserve manual bash script injections inside the ebuild string generation loop so that rerunning the generator does not result in a loss of functionality for edge-case packages.

### 2. Full Configuration Property Pass-through
**Issue:** The generator currently hardcodes strings or misses parsing certain metadata fields specified in the config or originally managed manually. For example, it defaults to `--m "gentoo@arran4.com:Arran Ubels:person"` in the `g2 metadata` command, and it doesn't correctly export `HOMEPAGE` for AppImages if not fully supported. This is tracked in https://github.com/arran4/arrans_overlay_workflow_builder/issues/69
**Feature Request:** Support comprehensive property assignments in `current.config` such as `MaintainerEmail`, `MaintainerName`, and ensure that `HOMEPAGE` and `LICENSE` properties correctly flow into all generated templates without defaulting to placeholders like `unknown`.

### 3. Bash Context Evaluation Handling for Binary Paths
**Issue:** The generator writes `${TAG}` instead of `${tag}` in the `SRC_URI` and manifest download urls strings if defined in the config. Because `cat <<EOT` natively disables bash evaluation, and `${TAG}` is not explicitly declared inside the Bash workflow loop (`${tag}` is), the evaluation resolves to an empty string breaking the manifest upserter.
**Feature Request:** Standardize and explicitly document internal variable mapping (`${tag}` vs `${TAG}`) for the `Binary` directive in `current.config`, and ensure the tool emits correct shell variables matching the Bash environment variable scope loop declarations.
